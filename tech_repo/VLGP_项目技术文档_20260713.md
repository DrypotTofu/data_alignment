# VLGP 手术机器人系统 — 项目技术文档

> **文档目的**：供 KimiCode 跟进项目进度，包含所有关键决策、技术方案与待办事项。  
> **最后更新**：2026-07-13  
> **项目定位**：手术场景下的 Vision-Language-Guided Pose (VLGP) 系统，非端到端 VLA，采用分层模块化架构。

## 1. 项目概述

### 1.1 核心目标
构建一套手术机器人数据采集与控制系统，实现：
- **多模态数据同步采集**：内窥镜主视角 + 腕部相机 ×2 + 机器人位姿（1kHz）
- **语言指令驱动的目标位姿预测**：输入图像 + 语言指令 → 预测目标位姿（非直接动作）
- **传统机器人学执行**：通过 IK + 插值将目标位姿转化为机器人运动，确保可解释性与安全性

### 1.2 与标准 VLA 的区别
| 维度 | 标准 VLA (如 SRT-H) | 本项目 VLGP |
|------|---------------------|-------------|
| 输出 | 直接输出动作序列/关节角 | 输出目标位姿 (Cartesian Pose) |
| 执行 | 端到端 | 传统 IK + 轨迹插值 |
| 优势 | 端到端优化 | 可解释、可验证、安全、符合手术规范 |
| 投稿注意 | — | 需明确区分于端到端 VLA，强调分层架构优势 |

### 1.3 参考模型与 Benchmark
- **参考架构**：SRT-H (Surgical Robot Transformer Hierarchical) — 高层语言策略 + 低层轨迹策略
- **相关 Benchmark**：
  - **SurgVLA-Bench** (2026)：首个腹腔镜手术 VLA 综合评估基准，基于 SurRoL 仿真环境，8 个层次化任务
  - **SutureBot** (2025)：dVRK 物理平台，1,890 个缝合演示数据集，评估 π0 / GR00T N1 / OpenVLA-OFT
  - **SurgMLLMBench**：手术多模态场景理解基准，用于评估感知模块

| 设备 | 型号/状态 | 采集方式 | 时间戳能力 | 优先级 |
|------|-----------|----------|------------|--------|

| **机器人控制器** | 倍福 TwinCAT | Scope 抓取 / ADS 实时通信 | μs 级精度 | 🔴 高 |
| **机器人本体** | dVRK (da Vinci Research Kit) | ROS/ROS2 接口 | — | — |

### 2.2 海康内窥镜主机背部接口（已确认）

从实物照片确认，背部具备以下可用接口：
- **Ethernet**：已插网线 ✅ — 首选方案，支持海康 SDK (MVS/HCNetSDK) 取流，可获取 ms 级设备时间戳
- **HDMI OUT**：备选方案，需外接 HDMI→USB3.0 采集卡，时间戳为帧到达 PC 时间（延迟 30~150ms）
- **12G-SDI OUT**：专业级无压缩视频，需专业采集卡（Blackmagic DeckLink），成本高
- **USB2.0**：大概率非视频输出，仅用于导出/控制
- **HCOM1/HCOM2**：海康专用通信口，非标准以太网

**接入决策**：优先尝试 **Ethernet + SDK** 取流，若不可行则 fallback 到 **HDMI + 采集卡**。

## 3. 数据采集与同步方案（核心）

### 3.1 同步策略：软同步（时间戳对齐）

由于硬件触发同步不可行（USB 相机无外部 trigger，海康设备独立），采用 **统一时间戳 + 事后对齐**。

#### 时钟基准
- **主时钟**：TwinCAT 实时时钟（μs 级精度）
- **从设备**：采集 PC 通过 **NTP** 与 TwinCAT 同步
- **USB 相机**：使用 `time.time_ns()`（CLOCK_REALTIME）记录帧到达时间
- **海康内窥镜**：若 SDK 支持，获取 `nDevTimeStamp`；否则使用帧到达时间

### 3.2 存储格式

推荐目录结构（逐帧存储 + CSV 索引）：

```
session_001/
├── hikvision_endo/          # 海康内窥镜
│   ├── 帧图像或视频文件
│   └── timestamps.csv       # 时间戳索引（如有）
├── wrist_left/
│   ├── 1234567890123456789.png   # 文件名 = 时间戳(ns)
│   └── metadata.csv          # idx, timestamp_ns, filename
├── wrist_right/
│   └── ...
└── twinCAT_poses.csv        # timestamp_ns, x, y, z, qw, qx, qy, qz, jaw
```

### 3.3 对齐算法（以内窥镜为基准时间轴）

| 数据类型 | 对齐策略 | 原因 |
|----------|----------|------|
| **TwinCAT 位姿** | 线性插值 LERP（位置）+ 球面插值 SLERP（旋转） | 位姿频率高（1kHz），可精确插值 |
| **USB 腕部相机** | 最近邻（阈值内） | USB 相机约 30fps，不宜插值 |
| **海康内窥镜** | 基准锚点 | 作为系统主视角 |

**关键细节**：
- 四元数插值前需处理符号一致性（`q` 和 `-q` 等价）
- USB 相机允许的最大时间 gap：建议 ≤ 50ms（约 1~2 帧）
- 若海康无时间戳，采用 **人工同步标记**（LED 闪烁/拍手）作为 `t=0` 偏移，精度约 1~3 帧（33~100ms）

### 3.4 文献支撑

- **SurgSync** (arXiv:2603.06919, JHU & UBC)：dVRK 多模态时间同步框架，Online-Matching（容差 10ms）+ Offline-Matching（最近邻 + 插值）
- **Nature Communications** (骨盆骨折复位)：统一时间戳 + 共同起始事件对齐
- **Multi-Camera Synchronization** (arXiv 2025)：无硬件触发场景下，通过跨视角运动轨迹估计时间偏移
- **WALL-OSS** (arXiv 2025)：VLA 大数据集构建中，多传感器时间戳同步作为数据质量第一道门槛

### 4.3 Docker 使用策略

| 场景 | 是否 Docker | 说明 |
|------|-------------|------|
| VLA 模型训练/推理 | ✅ **推荐** | `nvidia/cuda` 基础镜像，PyTorch + Transformers |
| 数据对齐脚本开发 | ✅ **推荐** | 依赖固化，便于迁移 |
| ROS 算法开发（非实时） | ✅ **可以** | `ros:humble-desktop` 官方镜像 |
| USB 摄像头采集 | ⚠️ **可以但麻烦** | 需 `--device /dev/video0` 映射 |
| TwinCAT ADS 通信 | ⚠️ **可以** | 需 `--network host` |
| dVRK 实时控制 | ❌ **不推荐** | 1kHz 控制循环，Docker 调度延迟不可接受 |

**迁移方案**：
- 开发完成后，`docker save` 导出镜像，`docker load` 导入新机器
- 数据卷挂载 `-v` 持久化，代码用 Git 管理
- 跨机器 ROS 通信：`--network host` 共享网络栈，或显式配置 `ROS_MASTER_URI`

## 5. 关键代码与配置

### 5.1 USB 相机采集（ROS2 Python 节点）

核心要求：
- 独立线程采集，不阻塞 ROS 主循环
- 帧到达时记录 `time.time_ns()`（不是 `read()` 调用时间）
- 逐帧保存 PNG，文件名为时间戳
- 生成 `metadata.csv` 索引
- 发布 ROS Topic：`/camera/wrist_left/image_raw`

**关键参数**：
- `cv2.CAP_PROP_FOURCC = MJPG`（节省 USB 带宽）
- 多相机插到不同 USB 控制器（`lsusb -t` 检查）
- 帧率不稳定时，记录实际时间戳，不假设固定 FPS

### 5.2 TwinCAT ADS 配置

**PLC 端**：
- 变量声明于 `MAIN` 程序，`PlcTask` 勾选 **"Create symbols"**
- 编译 → Login → 运行（图标变绿色）

**路由配置**（`C:\TwinCAT.1\Target\StaticRoutes.xml`）：

```xml
<TcConfig>
  <RemoteConnections>
    <Route>
      <Name>MyPC</Name>
      <Address>192.168.1.50</Address>
      <NetId>192.168.1.50.1.1</NetId>
      <Type>TCP_IP</Type>
      <Flags>0</Flags>  <!-- 关键！0 允许非 Windows/Linux 客户端 -->
    </Route>
  </RemoteConnections>
</TcConfig>
```

**Python 端**（`pyads`）：
- `ams_net_id`：PLC 的 AMS Net ID（IP + `.1.1`）
- `ams_port`：`851`（TC3 默认）
- `ip_address`：PLC 的 IP
- `local_ams_net_id`：PC 的 AMS Net ID（Linux/Docker 场景必须显式指定）

### 5.3 dVRK 控制接口

- `servo_cp()`：笛卡尔空间伺服，适合 VLA 输出末端位姿
- `move_cp()`：带插值的轨迹生成，比 `servo` 更平滑，适合长程操作
- `servo_jp()`：关节空间伺服
- 启动命令：`ros2 run dvrk_robot dvrk_system`

## 7. 关键决策记录

| 日期 | 决策 | 理由 | 备选方案 |
|------|------|------|----------|
| 2026-07-12 | 采用 **软同步**（时间戳对齐） | 硬件触发不可行（USB 无 trigger，海康独立） | 工业相机 + 硬件触发（长期） |
| 2026-07-12 | TwinCAT 时钟作为主时钟 | μs 级精度，最高 | GPS/PTP（更复杂） |
| 2026-07-12 | 以内窥镜为基准时间轴 | 主视角，决策频率最低 | 以 TwinCAT 为基准（需降采样） |
| 2026-07-12 | VLGP 定位为 **非端到端** | 可解释、安全、符合手术规范 | 端到端 VLA（SRT-H 风格） |
| 2026-07-13 | 海康优先 **Ethernet + SDK** | 可获取设备时间戳，精度最高 | HDMI + 采集卡（fallback） |
| 2026-07-13 | 部署采用 **ZMQ + ROS2 混合** | 解耦推理与实时控制 | 纯 ROS（模型太重） |
| 2026-07-13 | Docker 用于开发/推理，**实时控制放宿主机** | 确保 1kHz 控制实时性 | 全 Docker（不推荐） |
