# VLGP 手术机器人系统 — 项目进展报告（2026-07-17）

> **文档目的**：汇总 2026-07-13 至 2026-07-17 的技术进展、关键发现与下一步待办事项，用于总结汇报和团队讨论。  
> **最后更新**：2026-07-17  
> **项目定位**：手术场景下的 Vision-Language-Guided Pose (VLGP) 系统，非端到端 VLA，采用分层模块化架构。

---

## 1. 项目目标回顾（保持不变）

构建一套手术机器人数据采集与控制系统，实现：

- **多模态数据同步采集**：内窥镜主视角 + 腕部相机 ×2 + 机器人位姿（1kHz）
- **语言指令驱动的目标位姿预测**：输入图像 + 语言指令 → 预测目标位姿（非直接动作）
- **传统机器人学执行**：通过 IK + 插值将目标位姿转化为机器人运动，确保可解释性与安全性

与标准端到端 VLA 的核心区别：本项目输出的是**目标位姿 (Cartesian Pose)**，而非直接动作序列。

## 3. 问题排查记录

### 3.1 初始问题：ping 不通机器人

**原因**：PC 以太网口为 APIPA 地址 `169.254.231.33`，与机器人 `192.168.22.22` 不在同一网段。  
**解决**：给 PC 以太网口手动添加静态 IP `192.168.22.50/24`。

### 3.2 ADS 报 `Missing ADS routes (7)`

**原因**：本地 TwinCAT 路由表为空。  
**解决**：在 `C:\TwinCAT\3.1\Target\StaticRoutes.xml` 中添加机器人路由，并重启 `TcSysSrv`。

### 3.3 ADS 报 `Port disabled (18)`

**原因**：最初本地路由表使用的 AMS NetID 是猜测的 `192.168.22.22.1.1`，与机器人实际 NetID `169.254.226.99.1.1` 不匹配。  
**解决**：核对既有 Scope 项目中的 `AmsNetId` 字段，修正本地路由。

### 3.4 机器人侧 ping 不通 PC

**原因**：PC Windows 防火墙阻止了来自机器人网段的入站 ICMP/ADS。  
**解决**：将以太网设为专用网络，并添加 ICMP 和 TCP 48898 入站规则。

### 3.5 机器人侧 PLC 状态

**状态**：调试过程中曾出现 Start / Restart 后 PLC 进入 STOPPED；后续重新操作后已能读取变量。  
**当前结果**：`pyads.read_state()` 返回 `(5, 0)`（ADSSTATE_START），`read_list_by_name()` 可稳定读取变量。PLC 是否能长期保持 RUN 仍需机器人工程师持续观察。

### 3.6 四元数顺序待确认

**状态**：`EndEffector_Orientation` 返回 4 个分量，当前按 `wxyz` 输出到 CSV。  
**待确认**：该四元数在机器人侧是 `(w, x, y, z)` 还是 `(x, y, z, w)`，需要机器人工程师确认。确认后可在 `twincat.py` 的 `orientation_order` metadata 中修正。

### 3.7 本地重启 TcSysSrv 报 `RTIME: incompatible software detected`

**原因**：本地 PC 的 TwinCAT 实时内核与 Hyper-V / 内存完整性等虚拟化特性冲突。  
**影响评估**：当前仅把本地 PC 当作 ADS 客户端使用，**不需要本地实时内核**。`TcSysSrv` 服务已在运行，不影响与远程机器人的通信。若未来需要在本地 PC 上运行 TwinCAT Runtime，则需先禁用相关虚拟化功能。
