## 1. 我们要复现什么

目标工作是 **SRT-H**（Surgical Robot Transformer Hierarchy，arXiv 2505.10251）：JHU 在达芬奇手术机器人上实现的分层式自主手术框架——高层模型根据视频与语言指令生成任务级指令（如「夹持针尖」），低层模型把指令翻译成关节级动作，完成缝合等长时序任务，且具备自我纠错能力。其前身 SRT（arXiv 2407.12998）验证了「视频 + 机器人状态 → 动作」的模仿学习路线。

复现这套方法的前提是**与原文同构的数据管线**：同步采集多路相机视频与机器人运动学数据 → 时间对齐 → 清洗/标注 → 构建成「图像 + 状态 + 动作 + 语言指令」的训练样本。我们参考了 SRT-H 作者团队开源的采集框架（jackzhy96/dvrk_multimodal_data_collection，含相机标定、多模态同步落盘与标注 GUI 的做法），在我们的国产四臂手术机器人平台上重建了整条管线。

**我们当前所处阶段**：采集与对齐基础设施已就绪并通过验证，下一步是标定闭环和正式演示数据采集。

图像以**无损 PNG** 逐帧落盘（保证训练数据质量；压缩等级 L1 在画质无损与存储开销间取平衡，已实测可长期承受；不压缩的 PNG0 方案 720p 约 150 GB/30 min，已否决）。

## 3. 数据采集方法

**核心问题**：视频流与 PLC 数据来自不同设备、不同进程、不同时钟，必须保证每条数据都有可信的统一时间戳。

我们的做法：

- **统一时钟**：所有数据打上采集 PC 的单调时钟时间戳。相机时间戳在 `cap.read()` 抓到帧的瞬间打点，PNG 编码与写盘在独立线程池（2–6 线程）异步完成——因此写盘抖动不会污染时间戳，只要求吞吐跟上。
- **PLC 时钟漂移修正**：PLC 与 PC 各自有钟，存在固定偏移 + 缓慢漂移（实测约 -32 ppm）。录制后拟合线性漂移模型 `t_pc = k·t_plc + b`，残差 std 约 **0.3 ms**（10 分钟量级 session 实测），把 PLC 数据全部折算到 PC 时钟轴。
- **启动编排**：TwinCAT 最先启动、三路相机并行预热后开录，消除开头大段无效数据和停止时的丢尾问题。
- **稳定性**：相机采集跑在独立 OS 进程（规避 Windows DirectShow 多相机冲突），进程死亡立即报错（fail-fast），不允许带病运行。
- 实测指标（30 秒与 10 分钟 session 均验证）：三路 30.0 fps、零丢帧、TwinCAT 300+ Hz 连续。

## 4. 时间对齐方法

策略：**以 30 Hz 内窥镜相机帧为锚点网格**，对每帧取各路最近邻相机帧，并把 PLC 高频位姿**插值**（位置 LERP / 姿态四元数 SLERP）到该时刻，输出一张统一对齐表——每行 = 一个 30 Hz 时刻的三路图像 + 四臂完整状态。

实测对齐质量：时间误差均值约 **0.9 ms**、p99 < 15 ms、机器人运动区间内覆盖率 **100%**。对 30 Hz（33.3 ms 周期）的训练数据而言，亚毫秒级误差远小于帧周期，满足模仿学习要求。

## 5. 训练数据构建（对齐 SRT-H 格式）

对齐表经人工裁剪（自研 PyQt5 评审工具：三路同步播放、首/尾无效段剔除、整段采纳/拒绝，非破坏式标注）后，构建为 episode 样本：

- **观测**：三路图像 + 机器人状态；
- **动作标签**（40 维/步）：末端**位置增量**（镜坐标系，内窥镜移动时自动含自我运动补偿）+ **姿态 6D 旋转增量** + 夹爪开合（归一化）+ 臂激活掩码；
- **语言与元数据**：任务指令、任务类型、器械类型等随 session 元数据自动透传。

数值合理性已做离线验证（静止段位置增量 ~0.05 mm 量级正确等）。

## 6. 现存问题

### 6.1 硬件 / 机电侧

1. **腕部相机成像质量**（已缓解，待长时验证）：480p USB 腕部相机白平衡曾锁定在暖色温（4600K），与内窥镜冷白 LED 照明不匹配导致蓝偏、直射区红通道过曝。已通过自动白平衡 + 手动曝光/色温回退方案解决，白纸标定流程已建立；**待 30 分钟长时演示确认无中途漂移**。
2. **标定尚未闭环**：相机内参（需棋盘格标定板现场采集）与手眼标定（见 6.2-1）都未做。这是正式采集前的硬前提。
3. **夹爪标定待实测**：已从数据反推出夹爪角度量程约 [-55°, +85°]，但「哪个方向是张开」需现场开/合动作实测确认（影响动作标签符号）。
4. **运行环境脆弱性**：机器人控制器 TwinCAT 实时内核曾因系统级冲突（RTIME 4132）无法启动，最终靠重装采集机系统 + 重建 ADS 双向路由解决。提示现场软硬件环境变更（系统更新、软件安装）可能破坏实时链路，需运维规范。

### 6.2 软件 / 方法侧

1. **姿态四元数坐标系（已与工程师确认，待标定）**：PLC 输出的姿态四元数定义在**机械臂基坐标系**，而我们的动作标签期望在**镜坐标系**（与内窥镜视野同系）。两者相差一个常值旋转 `R_arm`：内窥镜固定不动时误差是常值、短期可用；正式训练前需做一次手眼标定估计该固定变换（≥8 组臂部位姿 + 视觉观测，最小二乘求解）。
2. **镜坐标系定义未完全明确**：镜系原点/轴向、是否随内窥镜关节运动，尚待机器人工程师补充说明（影响对内窥镜移动场景自我运动补偿的理解与验证）。
3. **臂激活掩码阈值**：「该臂此刻是否在被操作」的判定目前是启发式阈值（0.05 mm/步 或 0.1°/步），需真实任务数据定稿。
4. **自动标注工具链缺口**：纠正指令自动生成（SRT-H 的纠错能力依赖此）与相/事件级标注 GUI 尚未实现，目前只有裁剪级人工清洗工具。

## 7. 希望请教与讨论的问题

1. **运动学坐标系**：器械姿态四元数从基座系转到镜系的最稳妥方案——数据侧标定固定旋转 vs 控制器侧直接输出镜系四元数，从机构/控制角度看哪个更可靠？
2. **手眼标定方案**：我们拟用「内窥镜固定 + 臂端标记物 ≥8 组位姿 + 棋盘格标定板」估计固定变换，请老师从标定误差来源（标记物安装、位姿选取分布、最小二乘残差判据）角度给建议。
3. **镜坐标系定义**：镜系如何随内窥镜关节运动？对内窥镜移动中的自我运动补偿是否有更好的定义方式？
4. **夹爪开合方向**：希望安排一次现场实测（开→闭→开）确认符号方向，顺带确认夹爪传动间隙对 30 Hz 动作标签的影响是否可忽略。
5. **平台运动学数据可信度**：30 Hz 训练数据对 PLC 位姿精度（重复定位、关节间隙、传动误差）的敏感程度如何评估？是否需要安排精度验证实验？
