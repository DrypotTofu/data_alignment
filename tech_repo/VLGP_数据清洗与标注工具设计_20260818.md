# VLGP 数据清洗与标注工具设计（2026-08-18）

**日期**：2026-08-18
**文档性质**：设计规范。对应 `AGENT_HANDOFF.md` T10。目标是解决采集数据开头/结尾无关片段的人工裁剪问题，并为后续人工标注（子任务段、纠正段）铺路。参考对象：`dvrk_multimodal_data_collection` 的 `data_annotation/`（PyQt5 GUI），但我们做大幅简化。
**相关文档**：`VLGP_标定与元数据规范_20260817.md`（session 元数据）、0803 备忘 13.3/13.5 节（episode 结构与 HL 纠正指令）。

---

## 1. 核心设计判断

dvrk 的标注 GUI（`data_annotate.py`，约 4000 行）复杂，是因为它逐模态标注（phase/event/contact 各自打在独立帧序列上）。我们已有 **30 Hz 对齐网格**（`align_camera_anchor.py` 输出的 `camera_anchor_alignment.csv`）：每行已把三路相机帧 + 四臂位姿同步到同一时刻。因此：

- **裁剪 = 在网格上选一个行区间** `[start_row, end_row]`，一个决定同时作用于所有模态；
- **段标注 = 在网格行上打标签**，天然跨模态对齐；
- 工具复杂度可控在单文件 600–800 行，不引入 Hydra，不拆分模块。

## 2. 非破坏式数据流（不可妥协的原则）

- 原始 session 文件永不修改、永不删除。人工决策全部写入 sidecar：`<session>/annotations.json`。
- 裁剪在 `build_srth_dataset.py` 构建 episode 时才生效（过滤网格行）。
- 随时可改 annotations.json 重建 episode，原始数据可回溯。

### 2.1 `annotations.json` schema（v1）

```json
{
  "version": 1,
  "reviewed_by": "operator_name",
  "reviewed_at": "2026-08-18T15:00:00+08:00",
  "status": "approved",
  "reject_reason": "",
  "trim": {"start_row": 123, "end_row": 4567},
  "segments": [],
  "flags": [],
  "notes": ""
}
```

字段说明：

| 字段 | 取值 | 说明 |
|---|---|---|
| `status` | `approved` / `rejected` / `pending` | 整条 session 的处置结论 |
| `trim` | 网格行号闭区间 | v1 核心；row 以 `camera_anchor_alignment.csv` 行序为准 |
| `segments` | `[{label, start_row, end_row}]` | v1 保留结构不启用；v2 用于子任务段/纠正段 |
| `flags` | 字符串枚举数组 | 如 `motion_blur` / `scope_moved` / `occlusion`，供训练侧过滤参考 |
| `notes` | 自由文本 | 异常情况 |

## 3. GUI 工具：`scripts/tools/review_session.py`

### 3.1 界面布局

```text
┌──────────────────────────────────┬───────────────┐
│                                  │ wrist_left    │
│        endoscope (arm_2) 大图     │  (arm_1)      │
│                                  ├───────────────┤
│                                  │ wrist_right   │
│                                  │  (arm_3)      │
├──────────────────────────────────┴───────────────┤
│ 运动量曲线（位移模长 + gripper_angle，可点击跳转）    │
├──────────────────────────────────────────────────┤
│ ◀◀ ◀ ▶ ▶▶  播放/速度  [IN] [OUT]  状态  保存  下一条 │
└──────────────────────────────────────────────────┘
```

### 3.2 关键交互

- **运动量曲线是裁剪效率的核心**：用网格已有位姿列离线计算每行位移模长与 gripper_angle 绘成曲线；开头/结尾的静止垃圾段一眼可见，点击曲线跳转到对应帧。
- 快捷键：`[` / `]` 打 IN/OUT 点；`←`/`→` 逐帧；`J/K/L` 穿梭（后退/暂停/前进，重复按加速）；`S` 保存；`N` 保存并下一条；`1/2/3` 切换 approved/rejected/pending。
- 播放速度 0.5x/1x/2x/4x；三路视图同步刷新。

### 3.3 性能方案

- 按帧 `cv2.imread` 按需解码 + 后台 `QThread` 预取环形缓存（默认前后各 90 帧）。
- 网格行 → 帧文件名的映射直接读对齐表列（`anchor_filename` / `camera_arm_*_filename`），不做任何文件系统扫描。
- 目标：720p 三路 4x 快放不卡顿；不允许在 GUI 线程解码。

### 3.4 批量队列模式

- `python scripts/tools/review_session.py --sessions sessions/`：列出全部 session，按 `review_manifest.json` 过滤出 `pending` 的逐条审。
- 全局清单 `<sessions_root>/review_manifest.json`：`{session_name: {status, reviewed_at, has_annotations}}`，审完自动跳下一条。
- 单条模式：`--session sessions/<name>`。

### 3.5 约束

- 单文件、无 Hydra、无额外配置文件；任务词汇表后续用 vocab JSON（v2 再引入）。
- 依赖仅 PyQt5 + cv2 + pandas + numpy（环境已具备，2026-08-18 已装 PyQt5 5.15）。

## 4. 与现有管线的集成

1. **前置**：session 已跑过 `align_camera_anchor.py`（本来就在标准管线里）。GUI 只读对齐表与帧文件，不重算对齐。
2. **`build_srth_dataset.py` 改造**（tools 层，T10 一部分）：
   - 自动检测 `<session>/annotations.json`；
   - `status == "rejected"` → 跳过并提示；
   - 按 `trim` 过滤网格行后再生成动作/chunk/HL 样本；
   - trim 区间与 annotations 版本记入 episode `meta.json`。
3. **v2 预留**：`segments` 启用后接备忘 13.3.5 节的纠正指令生成；`session_meta.json` 的 task_instruction 在 GUI 中只读展示。

## 5. 验收标准（T10 v1）

- 在 `sessions/20260817_124143`（10 分钟长稳 session）上完成一次完整评审：打 IN/OUT、保存、重进后状态正确恢复。
- 批量模式能枚举 `sessions/` 下全部 session 并正确维护 `review_manifest.json`。
- `build_srth_dataset.py` 对带 annotations 的 session 输出的 episode 行数 = trim 区间长度（±尾部 chunk 丢弃），`meta.json` 含 trim 记录。
- 4x 快放流畅（主观不卡顿），逐帧步进响应 < 100 ms。

## 6. 明确不做（v1 范围外）

- 段标注（segments）编辑 UI、纠正段标记 → v2。
- 视频转码/预览文件生成（直接读 PNG 帧）。
- 多用户协作、权限、Web 化。
