## 1. 项目目标

构建一套面向机器人辅助手术的多模态数据采集平台，同步记录：

- **视觉数据**：内窥镜主视野（arm_2）+ 双臂手腕相机（arm_1 / arm_3）
- **运动学数据**：通过 TwinCAT ADS 从倍福 PLC 读取机器人末端位姿
- **时间对齐**：为后续跨模态数据对齐提供可靠的时间基准

当前阶段：**采集平台基础功能已完成，硬件能力已摸清，跨模态时间对齐方案已验证。**

## 4. 已验证的关键结论

### 4.1 独立进程采集稳定

- 每个相机独立 OS 进程，互不干扰。
- 5 分钟连续测试通过，无进程崩溃、无严重丢帧。

### 4.2 TwinCAT 多连接有效但 PLC 端是瓶颈

- 单连接：~320 Hz
- 双连接：~650 Hz，但伴随大量重复 CycleCount
- 结论：Python 端优化已到位，继续提升到 1 kHz 需检查 PLC 任务周期 / ADS 路由

### 4.3 跨模态时间对齐方案已验证（2026-08-03 样例）

**方案**：以 PLC 时间轴为统一参考，将视频帧的 PC wall time 通过线性映射转换到 PLC 时间，再找最近邻 TwinCAT 位姿。

**模型**：`timestamp_ns_plc = k * timestamp_ns_pc + b`

**样例 `sessions/test_20260803_104724` 结果**：

| 相机 | 有效帧数 | 平均对齐误差 | 标准差 | 最大误差 |
|---|---|---|---|---|
| camera_arm_1 | 1,717 | **0.83 ms** | 0.52 ms | 2.91 ms |
| camera_arm_2 | 2,379 | **0.84 ms** | 0.51 ms | 2.34 ms |
| camera_arm_3 | 1,666 | **0.84 ms** | 0.51 ms | 2.11 ms |

**结论**：对齐精度在 1ms 以内，方案可用。建议优先使用 `scripts/tools/verify_alignment.py`。

## 6. Agent 快速参考

### 6.1 如何恢复上下文

1. 读取本文件。
2. 读取 `scripts/config/default.yaml` 了解当前硬件分配。
3. 查看最新 session 目录分析结果（如有）。

### 6.2 常用命令

```bash
# 验证摄像头分配
conda run -n SurgDataColl python scripts/tools/camera_assignment_setup.py

# 手动采集
conda run -n SurgDataColl python scripts/tools/manual_acquisition.py

# 验证对齐
conda run -n SurgDataColl python scripts/tools/verify_alignment.py --session sessions/<session_name>

# 运行指定时长测试
conda run -n SurgDataColl python scripts/run_acquisition.py --config scripts/config/default.yaml --duration 300 --name test_name
```

### 6.3 常见陷阱

- **不要**把 `clock_source` 改回 `twincat_master` 做实时视频时间戳对齐；改为事后校准。
- **不要**把 `.bat` 文件保存为 UTF-8 + LF；必须为 **GBK + CRLF**。
- arm_1 / arm_3 的 22.5 fps 是物理上限，不要试图通过降分辨率/改编码来提升。
- 重新插拔 USB 相机后必须重新运行 `camera_assignment_setup.bat`。

### 6.4 最值得优先处理的问题

1. 把 `default.yaml` 中 arm_1 / arm_3 改为 `jpg` + `fps: 22`。
2. 做一次 10–30 分钟长时间稳定性测试。
3. 如果需要，把 `verify_alignment.py` 的最近邻策略升级为插值策略。
