## 四、MDH → FK 方程与示例结果（T16，供工程师对接）

### 4.1 约定与逐连杆变换

Modified DH（与 PLC 一致），每个连杆的齐次变换：

```
T_i = Rx(alpha_i) · Tx(a_i) · Rz(theta_i) · Tz(d_i)
```

展开为 4×4 矩阵（`ct=cos θ, st=sin θ, ca=cos α, sa=sin α`，单位：`a`/`d` mm，`θ`/`α` deg）：

```
        |  ct    -st·ca    st·sa    a·ct |
T_i  =  |  st     ct·ca   -ct·sa    a·st |
        |   0      sa       ca       d   |
        |   0       0        0       1   |
```

关节类型（镜像 PLC `EN_JointMotionType`）：

- `fixed`：θ = θ_i（零位偏置），d = d_i，不驱动
- `revolute`：θ = θ_i + q，d = d_i
- `prismatic`：θ = θ_i，d = d_i + q

正运动学：`T = ∏ T_i`（i=0..12，13 行），末端位置 `p = T[:3,3]`，姿态 `R = T[:3,:3]`。

### 4.2 每臂 13 行结构（源自 `tech_repo/MDH参数表.md`，2026-08-20）

### 4.3 CSV joint_1..12 → MDH 行的映射（T16 假设，待验证）

`fk(arm_id, joints[12])` 中 `DRIVEN_MDH_ROWS = (1..11)`（行索引 1–11，即 j4..j14/15 共 11 个驱动行），
按顺序消费 `joint_1..joint_11`；行 0（j3）与行 12（jaw）为 fixed。

**⚠️ 待确认项（joint_12）**：CSV 提供 `joint_1..joint_12` 共 12 个值，而默认映射只消费前 11 个——
**`joint_12` 恒未使用**。两种可能：① 行 11（j14/15）或某驱动行应对应 joint_12（映射右移）；② MDH 表第 12 行本就不驱动。
**结论需工程师确认**（单关节逐个运动实验，协议见 `tech_repo/T16_FK与PLC对标验证_20260821.md` 第四节）。
确认前不修改消费逻辑。

## 五、build_srth_dataset 孤儿末帧记录（2026-08-30 决策：保留）

**现象**（评审 2.3）：`build_srth_dataset.py` 中 `obs/` 与 manifest 镜像**对齐网格**（`len(grid)` 帧），
而 `actions.parquet` 只覆盖**网格转移**（`len(grid)-1` 行，delta 动作），因此存在一张无 actions 行引用的
"孤儿末帧"（网格最后一行对应的相机帧，文件名 `frame_{len(grid)-1:06d}.<ext>`）。

**判定与决策（2026-08-30）**：这是**结构性设计**而非 bug——网格行是"该行是哪一帧"的真值来源，
动作行是"帧间转移"；保留末帧便于边界目检。**行为保持不变**，已在代码 `kept_files` 构造处加注释说明。
导出器（`export_lerobot`）按 actions 行读取，不受影响。若将来希望 `obs/` 严格镜像 actions，
需删除网格最后一行帧并同步 manifest（一行改动，当前不做）。
