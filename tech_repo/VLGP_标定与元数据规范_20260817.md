## 1. 背景与目标

### 1.1 为什么现在做

- 参考仓库 `dvrk_multimodal_data_collection`（SurgSync）每条 clip 都带 `camera_calibration/` 与 `hand_eye_calibration/`；我们目前完全没有标定文件采集步骤。
- 内窥镜对焦/位置一旦变动，事后无法补标定 → 标定必须在正式采集前就位，且随 session 可追溯。
- 相机 index 0–3 已可用（2026-08-17 实测，绑定：arm_1=1、arm_2=0、arm_3=3），本任务只依赖相机，不依赖 TwinCAT，可立即执行。

### 1.2 本规范覆盖

1. 内参标定流程（内窥镜 arm_2 + 腕部相机 arm_1/arm_3）。
2. 标定文件存放路径与命名约定。
3. 每个正式 session 的 meta 中记录所用标定文件（标定 ID / 日期 / 版本）。
4. Session 级元数据模板（T8）与操作者采集流程。

## 2. 内参标定流程设计

### 2.1 标定板选择

- **推荐**：标准棋盘格（checkerboard）或 ChArUco 板。本项目环境已带 `cv2.aruco`（OpenCV 5.0.0 验证可用）。
- 建议参数：内角点 9×6（或 10×7），方格边长 20–25 mm（打印后实测为准）。
- 若后续需要手眼标定（T9 相关），同一标定板可复用。

### 2.2 采集流程（每条相机独立）

1. 用 `scripts/tools/collect_calibration.py` 打开目标相机（逐台打开，避免多相机 DSHOW 冲突；也可参考 `preview_connected_cameras.py` 的多路方式）。
2. 操作者将标定板置于镜头前，覆盖不同位姿：
   - 中心 + 四个角落（板占画面 30–80%）；
   - 不同倾斜角（前倾/后倾/左右偏转）；
   - 不同距离（近/中/远）。
3. 实时检测角点，**检测成功的帧**按空格键保存（工具内实时显示角点数）。
4. 每台相机保存 **15–25 张**合格帧（OpenCV `calibrateCamera` 建议 ≥10 张、覆盖全画面）。
5. 采集完成后运行内参计算（同一工具内或单独 `--calibrate`），输出 `intrinsics.yaml`。

### 2.3 内参计算

- OpenCV `cv2.calibrateCamera()`，flags 默认（含 k1–k6、p1–p2 估计）。
- 输出：`camera_matrix`（3×3）、`dist_coeffs`（5–8 元素）、`reprojection_error`（RMS，验收线 < 0.5 px）、`image_size`。
- 同一物理相机、同一分辨率、同一对焦状态下，内参长期有效；**对焦/位置变动必须重新标定**。

## 3. 标定文件存放路径与命名约定

### 3.1 目录结构

```text
<repo>/calibrations/
└── calib_YYYYMMDD_HHMMSS/            # 一次标定活动（含三台相机）
    ├── calibration.json              # 标定会话 meta（见 3.2）
    ├── camera_arm_2/                 # 内窥镜（锚点相机）
    │   ├── frames/                   # 原始采集帧（png）
    │   ├── intrinsics.yaml           # K / D / RMS / image_size
    │   └── reprojection.png          # 标定质量可视化（可选）
    ├── camera_arm_1/                 # 腕部相机
    │   ├── frames/
    │   └── intrinsics.yaml
    ├── camera_arm_3/
    │   ├── frames/
    │   └── intrinsics.yaml
    └── hand_eye/                     # 预留：手眼标定结果（T9 确认后启用）
        └── README.md
```

- 根目录 `calibrations/` 与 `sessions/`、`packed/` 同级，加入 `.gitignore`（原始帧不入库；`intrinsics.yaml` 体积小，可选择性入库）。

### 3.2 标定会话 meta（`calibration.json`）

```json
{
  "calibration_id": "calib_20260817_203000",
  "created_at_beijing": "2026-08-17T20:30:00+08:00",
  "operator": "姓名/工号",
  "board": {"type": "checkerboard", "inner_corners": [9, 6], "square_mm": 22.5},
  "camera_bindings": {"arm_1": 1, "arm_2": 0, "arm_3": 3},
  "cameras": {
    "camera_arm_2": {"resolution": [1280, 720], "frames": 20, "rms_px": 0.23, "file": "camera_arm_2/intrinsics.yaml"},
    "camera_arm_1": {"resolution": [640, 480],  "frames": 18, "rms_px": 0.19, "file": "camera_arm_1/intrinsics.yaml"},
    "camera_arm_3": {"resolution": [640, 480],  "frames": 22, "rms_px": 0.21, "file": "camera_arm_3/intrinsics.yaml"}
  },
  "notes": "对焦固定后采集；后续如需变焦需重标"
}
```

### 3.3 标定 ID 命名

`calib_YYYYMMDD_HHMMSS`（本地时间，与 session 命名风格 `test_YYYYMMDD_HHMMSS` 一致）。

## 4. Session meta 记录所用标定文件

### 4.1 写入位置（方案）

两个层次：

1. **采集层（session.json）**：建议在 `scripts/acquisition/session.py` 的 `_write_session_json()` 中增加 `camera_calibration` 字段（值 = 标定 ID 或各相机 intrinsics 相对路径）。⚠️ **属 `scripts/acquisition/` 核心代码改动，需项目管理 Agent 确认后实施**（本文档即提案）。
2. **数据层（episode meta.json）**：`build_srth_dataset.py` 输出的 `meta.json` 中记录 `camera_calibration`（从 session.json 透传或 CLI 指定）。

### 4.2 过渡方案（不等框架改动即可用）

- 采集前，操作者将标定 ID 填入 `--name calib_xxx` 或 session 说明；或
- 用 `scripts/tools/write_session_meta.py`（T8 配套工具）在采集后向 `session.json` 追加 `camera_calibration` 与任务元数据（非核心代码，不改框架）。

### 4.3 验收

正式采集时，每个 session 的 meta 中能查到：该 session 使用了哪次标定（ID/日期/版本）、各相机 RMS、分辨率。

## 5. T8：Session 级元数据模板与任务指令采集规范

### 5.1 目标

`language.json` 目前是离线占位（`task_instruction: ''`）。正式采集时操作者必须**当场**记录任务信息，大规模采集后无法回溯补录。

### 5.2 Session 级元数据模板（`session_meta.json`）

```json
{
  "session_name": "20260817_203000",
  "task_instruction": "approach needle and grasp",   // 英文指令（与 SRT-H 风格一致）
  "task_type": "needle_touching",                    // 枚举：needle_touching / needle_grasping / autonomous_suturing / endoscope_adjust / other
  "subtask_sequence": ["approach", "grasp", "lift"], // 可选：子任务序列
  "operator": "姓名/工号",
  "organ_model": "编号/批次",                         // 组织/模型编号（如猪胆囊批次）
  "instruments": {"arm_1": "grasper", "arm_3": "needle_driver"},  // 可选
  "notes": "自由备注：异常、特殊情况等",
  "camera_calibration": "calib_20260817_203000"      // T7：所用标定 ID
}
```

### 5.3 写入位置（决定）

- **session 级**：`<session>/session_meta.json`（新文件，不侵入 session.json；或并入 session.json，见 4.1 提案）。
- **episode 级**：`build_srth_dataset.py` 生成 `language.json` 时，将 `task_instruction`、`task_type`、`organ_model` 从 session 级元数据**自动带入**（改造点，见 5.4）。

### 5.4 实施路径（不阻塞正式采集）

1. 新建工具 `scripts/tools/write_session_meta.py`：
   - 交互式填写（带默认值、枚举校验）或 `--json file.json` 导入；
   - 写入 `<session>/session_meta.json`；
   - 可选 `--merge-session-json`：将字段并入 session.json（保守模式默认关闭）。
2. 改造 `build_srth_dataset.py`：若 `<session>/session_meta.json` 存在，`language.json` 与 `meta.json` 读取其中字段，替代空占位。⚠️ `build_srth_dataset.py` 属 tools 层（非 acquisition 核心），但仍按汇报规范先行说明。
3. 操作者采集流程（一页）：见本文档第 6 节。

### 5.5 枚举定义（首版）

`task_type`: `needle_touching | needle_grasping | autonomous_suturing | endoscope_adjust | calibration | other`

## 6. 操作者采集流程说明（一页）

```text
正式采集前（一次性/对焦变动后）:
  1. 打印并实测标定板方格边长 → 记录 mm 值
  2. 逐台相机跑 python -m vlgp.calibration.collect_calibration 采集 15-25 帧 → 输出 calibrations/calib_<ts>/
  3. 检查各相机 RMS < 0.5 px；不达标则补采
  4. 记录标定 ID（calib_<ts>）

每次正式采集:
  1. 确认 default.yaml camera_bindings（arm_1=1, arm_2=0, arm_3=3）
  2. python scripts/run_acquisition.py --config scripts/config/default.yaml --name <session>
  3. 采集结束后立即: python -m vlgp.review.write_session_meta --session sessions/<session>   ← 当场填写任务信息（不可回溯）
  4. python -m vlgp.alignment.verify_alignment --session sessions/<session>   （预检链路）
  5. python -m vlgp.alignment.align_camera_anchor → python -m vlgp.dataset.build_srth_dataset → python -m vlgp.dataset.images_to_video 目检
  6. 检查 episode language.json 已含 task_instruction（从 session_meta 自动带入）
```
