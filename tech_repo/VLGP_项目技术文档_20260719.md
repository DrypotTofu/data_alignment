## 1. 项目目标

构建一套稳定、可扩展的多模态手术数据采集平台，用于同步记录：

- **视觉数据**：内窥镜（高清）+ 双臂相机（手腕视角）
- **运动学数据**：通过 TwinCAT ADS 从 PLC 读取机器人末端执行器位姿

采集结果以结构化 session 形式落盘，供后续时间对齐、数据清洗与模型训练使用。

## 2. 硬件配置

| 设备 | 连接方式 | OpenCV 索引 | 用途 | 备注 |
|---|---|---|---|---|
| 海康内窥镜 | 采集卡 → USB | `0` | 主视野 | 要求 ≥1280×720 |

## 3. 软件架构

### 3.1 核心模块

```text
scripts/
├── acquisition/
│   ├── session.py              # Session 编排器：统一时钟、目录、writer
│   ├── base_source.py          # 数据源抽象基类
│   ├── timestamp.py            # 统一时间戳工具
│   ├── sources/
│   │   ├── twincat.py          # TwinCAT ADS 源
│   │   ├── usb_camera.py       # 线程内 USB 相机源（已弃用于 arm_2）
│   │   └── usb_camera_process.py   # 独立进程 USB 相机源
│   └── process_workers/
│       └── usb_camera_worker.py    # 子进程采集 worker
├── tools/
│   ├── camera_assignment_gui.py    # GUI 摄像头分配
│   ├── preview_single_camera.py    # 单摄像头实时预览
│   ├── preview_connected_cameras.py # 批量探测摄像头能力
│   ├── manual_acquisition.py       # 手动启停采集
│   └── start_manual_acquisition.bat # 一键启动批处理
└── config/
    └── end_to_end_1min_test.yaml   # 当前主配置
```

### 3.2 设计要点

- **独立进程采集**：每个 USB 相机运行在独立 OS 进程（`process_camera`），避免 Windows DirectShow 多线程冲突，且单个相机的写盘瓶颈不会影响其他源。
- **统一 Session 管理**：`AcquisitionSession` 负责创建 session 目录、注册所有源、启动/停止采集、写入 `session.json`。
- **Writer 线程**：
  - 进程相机自包含 writer（子进程内）。
  - TwinCAT 数据由 Session 的主 writer 线程写入 CSV。
- **信号处理**：支持 `Ctrl-C` / `Ctrl-Break` 优雅停止。

## 4. 数据源与格式

### 4.1 视觉数据

| 字段 | 说明 |
|---|---|
| 存储格式 | PNG（arm_1 / arm_3）或 JPG（arm_2） |
| 命名规则 | `{source_name}_{frame_idx:08d}_{timestamp_ns}.{format}` |
| 元数据 | `metadata.csv`：index, timestamp_ns, pc_arrival_ns, timestamp_beijing, filename, width, height |
| 时间戳 | `timestamp_ns` 基于 `host_realtime`（`time.time_ns()`），单调递增 |

### 4.2 TwinCAT 机器人位姿

| 字段 | 说明 |
|---|---|
| 文件 | `robot_pose/twincat_poses.csv` |
| 主时间戳 | `timestamp_ns` = PLC CycleCount × CycleTime（PLC 时间轴） |
| PC 时间戳 | `timestamp_ns_pc` = 主机收到 ADS 响应时的 PC 时间 |
| RTT | `rtt_ns` = ADS 请求往返延迟 |
| 数据列 | 位置 (x,y,z)、四元数 (w,x,y,z)、关节角等 |

### 4.3 session.json

每个 session 根目录下的元数据文件，记录：

- session 名称、起止时间、持续时间
- `clock_source`、`clock_offset_ns`
- 各源样本数、配置摘要

## 6. 时间戳策略

### 6.1 当前策略：`clock_source = host_realtime`

- 视频帧的 `timestamp_ns` 使用 PC  wall time。
- TwinCAT 样本的主 `timestamp_ns` 使用 PLC CycleCount 时间（PLC 时间轴）。
- TwinCAT metadata 同时记录 PC 到达时间 `timestamp_ns_pc`。

### 6.2 为什么不用 `twincat_master`

早期尝试过 `clock_source = twincat_master`，由 TwinCAT 源动态更新 `offset_ns`，使视频时间戳对齐 PLC 时间轴。但发现：

- TwinCAT offset 随采集过程收敛/漂移。
- 不同相机子进程在启动时抓取的 offset 不同，导致跨相机时间戳不一致。
- 视频时间戳出现非单调甚至递减。

因此改为 `host_realtime` + 事后漂移校准方案（见第 9 节）。

### 6.3 事后对齐接口

TwinCAT CSV 已包含：

- `timestamp_ns`（PLC 时间）
- `timestamp_ns_pc`（PC 时间）
- `pc_arrival_ns`
- `twincat_cycle_count`
- `rtt_ns`

可据此建立 `PLC_time = f(PC_time)` 的线性映射，再校准视频 `timestamp_ns`。

## 7. 操作工具

### 7.1 摄像头分配：`camera_assignment_setup.bat`

- 双击运行。
- 探测 0-9 索引摄像头。
- GUI 显示每个摄像头的预览图。
- 用户选择每个摄像头对应哪条臂（arm_1/arm_2/arm_3）。
- 自动更新 `scripts/config/end_to_end_1min_test.yaml`。
- 未分配的臂会被标记 `enabled: false`。

### 7.2 单摄像头预览：`preview_single_camera.bat`

- 双击运行。
- 列出可用摄像头，用户输入索引。
- 实时预览，叠加分辨率、FPS、按键提示。
- 支持连续预览多个摄像头：关闭一个后询问是否继续。
- 快捷键：`q/ESC/X` 退出，`s` 保存快照。

### 7.3 手动采集：`start_manual_acquisition.bat`

- 双击运行。
- 自动生成 `test_YYYYMMDD_HHMMSS` 格式 session 名（北京时间）。
- 按 Enter 开始，按 Enter 停止。
- 实时打印各源样本数。

## 9. 已知问题与限制

### 9.1 已解决

| 问题 | 解决方案 |
|---|---|
| 内窥镜 1280×720 PNG 写盘跟不上 30 fps | 改为 JPG；独立进程避免拖累其他源 |
| 相机时间戳不单调/不一致 | `clock_source` 改为 `host_realtime` |
| 子进程输出路径错误 | `session_dir` 使用绝对路径 |
| 批处理闪退 | 转换为 GBK + CRLF；交互脚本只重定向 stderr |
| 点击 OpenCV 窗口 X 按钮无法退出 | 检测 `WND_PROP_VISIBLE` |

### 9.2 待解决 / 需讨论

| 问题 | 影响 | 建议方案 |
|---|---|---|
| `camera_arm_3` 使用 YUY2 时帧率约 22.5 fps | 右腕数据密度不足 | 改为 MJPG；若两台手臂相机同分辨率同格式冲突，可给 arm_3 分配 800×600 等差异化分辨率 |
| `robot_pose` 实际约 327 Hz，未达 1 kHz | 运动学时间分辨率受限 | 优化 ADS 读取路径、增加并行连接数、或接受 300 Hz 作为工作频率 |
| 手臂相机 PNG 存储占用大 | 1 分钟约 900 MB/相机 | 改为 JPG 或降低 PNG 压缩等级 |
| `camera_arm_3` 索引可能是笔记本摄像头 | 误把非手臂画面当右腕数据 | 重新运行 `camera_assignment_setup.bat` 确认 |
| 长时间采集稳定性 | 未知 | 建议做 5-30 分钟连续测试，观察队列、丢帧、磁盘 I/O |
| TwinCAT PLC 与 PC 时钟漂移 | 跨模态时间对齐误差 | 实现 `calibrate_temporal_drift.py` 的事后校准流程 |

### 9.3 已预留但未充分验证

- RTT 延迟校正（TwinCAT `use_rtt_correction`）。
- 多 ADS 连接（`num_connections`）。
- 事后漂移校准脚本 `scripts/tools/calibrate_temporal_drift.py`。

## 10. 下一步工作建议

1. **确认 camera_arm_3 的物理索引**：运行 `camera_assignment_setup.bat`，确保 arm_3 对应真实的 USB 手臂相机。
2. **提升 arm_3 帧率**：将 YUY2 改为 MJPG，必要时调整分辨率。
3. **长时间稳定性测试**：连续采集 10-30 分钟，检查丢帧、磁盘写入、内存占用。
4. **实现/验证事后时间校准**：用 TwinCAT 双时间戳建立 PLC-PC 映射，校准视频时间戳。
5. **评估存储策略**：若采集时长增加，考虑将手臂相机从 PNG 改为 JPG。
6. ** robot_pose 速率优化**：若 1 kHz 是硬性需求，需重构 TwinCAT 读取路径；否则明确接受 300-350 Hz。
